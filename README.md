# Karst Spring Catchment Approximation for Large-Sample Discharge Modelling and Application to a Global LSTM

Code accompanying the preprint:

**Thinius, P., Joger, F., Liesch, T., Goldscheider, N. (2026):** *Automated karst spring catchment approximation for discharge modelling*. EarthArXiv. DOI: XX

**Contact:** pauline.thinius@kit.edu

## Overview

This repository contains the code used to approximate catchment areas of karst springs and to evaluate the resulting catchment approximations using a global Long Short-Term Memory (LSTM) model.

The workflow consists of two main parts:

1. **Catchment approximation** — implemented in R 4.5
2. **Global LSTM** — implemented in Python 3.12

The catchment approximation combines recharge estimates and topographic catchment information to iteratively construct circular catchment approximations for karst springs.

The resulting catchment approximations are subsequently evaluated using a global LSTM rainfall–runoff model. The preparation of catchment-aggregated meteorological and static input data required for the LSTM follows the preprocessing workflow of the ALPAKAS dataset.

## 1. Catchment Approximation

### Requirements

The catchment approximation workflow was developed using **R 4.5**.

Required R packages are specified in the corresponding scripts.

### Running the Catchment Approximation

The main script is:

```text
Catchment_approximation/scripts/buffer_approx_main.R
```

Execute this script to run the catchment approximation workflow.

The script calls the functions required to:

1. estimate recharge,
2. compute topographic catchments, and
3. iteratively construct the circular catchment approximations.

Before running the script, make sure that all required input datasets are available in the directories described above.

### Output

Catchment delineation results are written to:

```text
Catchment_approximation/output_data/catchment_delineations/
```


## 2. Catchment Aggregation for Discharge Modelling

To use the derived catchment approximations for discharge modelling, meteorological and static input data need to be spatially aggregated over the respective catchment areas.

The code for this preprocessing step is **not included in this repository**. Catchment aggregation is performed following **Step 3 (Catchment Aggregation)** of the preprocessing workflow provided with the ALPAKAS dataset:

[ALPAKAS preprocessing repository](https://github.com/FelixJoger/ALPAKAS/blob/main/README.md)

For the analyses presented in the accompanying study, the catchment delineations generated by the catchment approximation workflow described above are used as the spatial units for aggregation.

This step produces catchment-aggregated meteorological time series and static attributes, which are subsequently used as input to the global LSTM model.


## 3. Global LSTM

### Requirements

The global LSTM workflow was developed using **Python 3.12**.

The model follows the architecture for in-sample discharge modelling described by **Liesch and Ohmer (2026)**. Static catchment attributes and dynamic meteorological input variables are combined using the concatenation approach described in that study.

Reference:

Liesch, T. and Ohmer, M. (2026).  
DOI: 10.5194/hess-30-1877-2026


### Folder Structure

```text
Global_LSTM/
├── scripts/
│   ├── preprocess_alpakas.py
│   ├── global_lstm.py
│   └── evaluation.py
├── preprocessed_data/
├── output_data/
└── plots/
```

`preprocessed_data/` contains the catchment-aggregated meteorological time series and static attributes prepared for input to the LSTM.

`output_data/` contains model predictions, evaluation results, and other outputs generated during model training and evaluation.


### Python Scripts

The global LSTM workflow consists of three Python scripts:

- **`preprocess_alpakas.py`** — Prepares the model input from the ALPAKAS aggregation output. The same procedure is used for reference catchments and catchment approximations, as both follow the same input format.
- **`global_lstm.py`** — Defines, trains, and runs the global LSTM model.
- **`evaluation.py`** — Computes the model performance metrics and discharge seasonality clusters used in the study.

                  │

        and static input data

                  │

                  │

                  │
